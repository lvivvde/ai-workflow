# game-design-knowledge 查询规则

使用 `game-design-knowledge` MCP 查询策划资料时，以下规则永久生效：

1. 只能依据 MCP 返回的文档证据回答。
2. 禁止根据常识、名称相似度、行业经验或模型记忆推断项目存在某个玩法。
3. 未找到证据时必须回答“当前已索引文档中未找到”，不得推荐相似玩法。
4. 设计意图只有文档明确说明时才能陈述。
5. 文档未记录的内容必须明确标记为未记录，不得补全。
6. 所有结论必须附文件、章节、段落、Sheet、行号或单元格等可用出处。
7. 文档冲突时只报告冲突和各自出处，不自行选择结论。
8. 禁止自动创建玩法别名；只有文档明确记载或用户明确确认后才能记录和使用。
9. 索引过期时必须先提示，再由用户决定是否重建。
10. 用户要求导入文件时，正式资料默认进入 `docs/docx/` 或 `docs/xlsx/`；只有用户明确说明是测试/示例资料时才进入 `examples/sample-corpus/`。
11. 默认复制文件；只有用户明确要求“移动”并理解原位置文件会消失时，才允许选择 `operation="move"`。
12. 写入前必须先调用 `plan_document_import`，完整展示源路径、目标路径、复制/移动方式以及冲突信息。
13. 只有用户针对该计划明确确认后，才能用完全相同的参数、`plan_token` 和 `confirmed=true` 调用 `import_documents`；不得把模糊回复当作确认。
14. 禁止覆盖同名资料，禁止直接修改 SQLite 表；必须通过导入或 `rebuild_shared_index` 原子重建。
15. 导入或重建失败时必须原样报告，不得声称索引已更新；成功后提醒将原始资料和 `.index/knowledge/` 一起提交。
16. 文件导入不代表玩法或别名已被确认，仍须遵守第 8 条。

建议将本文件中的规则复制到实际游戏项目的 `AGENTS.md` 或平台永久 Rules 中。
